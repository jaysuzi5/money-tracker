Backup Strategy

Money Tracker · last updated 2026-06-28

Question: is plain PostgreSQL backup enough?

Short answer: a tiered pg_dump to offsite S3 is the correct baseline — but for personal finance there is one meaningful improvement worth adding, so this app does both:

  1. Logical pg_dump (custom format, compressed) — exact, point-in-time database restore.
  2. Open-format QIF export — an application- and schema-independent copy of every account/transaction/split, re-importable into Quicken or a rebuilt Money Tracker even if the database, this app, or its schema no longer exists.
Why the QIF layer matters: a pg_dump is only restorable into a compatible PostgreSQL with this app's schema. For data you intend to keep for decades, that's fragile coupling. The QIF export is plain text in a 30-year-old standard format — it survives the app entirely. Belt and suspenders.

Storage class STANDARD_IA. Mirrors the vacation-planner pattern; same bucket, separate prefix.

Is there a still-better strategy? (considered, rejected)

OptionVerdict
Continuous WAL archiving / PITROverkill. This app ingests once/day; sub-second recovery granularity has no value for personal finance. The CloudNativePG cluster already takes base backups at the cluster layer.
Filesystem/volume snapshotsCouples backups to storage tech; pg_dump is more portable across PG versions.
Per-table CSV dumpsQIF already gives an open-format copy that round-trips through the app's own importer; CSV-per-table adds nothing.
pg_dump (tiered, offsite) + QIF exportCHOSEN Simple, portable, app-independent, cheap.

Restore procedures

From a pg_dump (full database)

# pull a dump from S3 (or the PVC), then:
pg_restore -h postgresql-rw.postgresql.svc.cluster.local -U money_tracker \
  -d money_tracker --clean --if-exists mt-YYYYMMDD-HHMMSS.dump

From QIF (app-independent rebuild)

# into a fresh Money Tracker (after migrate + seed_categories):
uv run python manage.py import_qif money-tracker-all.qif --institution <name>
# or import into Quicken: File > Import > QIF

On-demand export

  • UI: user menu → Export all (QIF), or per-account Export QIF on the register.
  • CLI: manage.py export_qif --output file.qif.

Setup note

The S3 cloud jobs require a money-tracker-s3 secret with aws_access_key_id / aws_secret_access_key (see k8s/s3-secret.example.yaml, seal with kubeseal). The local pg_dump and qif-export jobs run without it.
